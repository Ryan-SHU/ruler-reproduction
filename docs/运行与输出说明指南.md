# RULER 双模型复现运行与输出说明指南

## 一、前序准备

### 1.1 目录、环境与安全约定

本指南以 AutoDL 的 `root` 用户和已有 PyTorch 的 `base` 环境为前提，不额外创建虚拟环境。项目统一放在以下结构中：

```text
/root/paper_reproduction/
├── code/       # 本组 GitHub 仓库
└── ref/RULER/  # NVIDIA RULER 上游源码
```

所有 `ruler-repro` 命令均从 `/root/paper_reproduction/code` 执行。Qwen 与 Llama 共享任务条件和评价流程，但分别使用自己的分词器与输入模板生成数据，两个模型不能共用样本清单。

不得把 Hugging Face 令牌、GitHub 令牌、密码、服务器登录信息、模型权重、模型缓存或 Python 环境提交到项目仓库。命令中的令牌均通过交互式登录输入，不写入脚本或 Markdown 文件。

### 1.2 下载本组代码

在 AutoDL 终端执行：

```bash
cd /root
mkdir -p paper_reproduction
git clone https://github.com/Ryan-SHU/ruler-reproduction.git paper_reproduction/code
cd paper_reproduction/code
git switch main
git pull --ff-only
```

该仓库是私有仓库。B、C、D 必须先接受 GitHub 协作者邀请，并在 AutoDL 上完成 GitHub HTTPS 认证，才能克隆。

如果 `paper_reproduction/code` 已通过网页上传或已经克隆，则只需执行：

```bash
cd /root/paper_reproduction/code
git switch main
git pull --ff-only
```

四名成员均从 `main` 分支拉取代码。存在未提交修改时，先停止实验并与 A 沟通，不直接覆盖本地文件。

### 1.3 下载 RULER 上游源码

本组仓库不包含 NVIDIA RULER 源码，需要单独克隆到 `paper_reproduction/ref/RULER`：

```bash
cd /root/paper_reproduction
mkdir -p ref
git clone https://github.com/NVIDIA/RULER.git ref/RULER
```

若目录已经存在，不要再次克隆，改用：

```bash
git -C /root/paper_reproduction/ref/RULER fetch origin
git -C /root/paper_reproduction/ref/RULER switch main
git -C /root/paper_reproduction/ref/RULER pull --ff-only
```

实验期间不得修改 `ref/RULER`。本组的适配、消融、评分和汇总代码全部位于 `code/src`。

### 1.4 安装项目依赖

进入本组代码目录：

```bash
cd /root/paper_reproduction/code
python -m pip install -e .
python -m pip install -U huggingface_hub
```

`huggingface_hub` 提供 `hf` 命令行工具。官方支持使用 `hf auth login` 登录，并使用 `hf download ... --local-dir` 把模型下载到指定目录。[Hugging Face CLI 官方文档](https://huggingface.co/docs/huggingface_hub/en/guides/cli)

检查 PyTorch、CUDA、项目依赖和 `hf`：

```bash
python -c "import torch; print('cuda_available=', torch.cuda.is_available())"
python -c "import yaml, transformers, nltk, wonderwords, matplotlib, statsmodels; print('project dependencies: OK')"
hf --help
nvidia-smi
```

检查 `vLLM`：

```bash
python -c "import vllm; print('vllm: OK')"
vllm --help
```

如果第一条命令提示没有 `vllm`，再安装与 AutoDL 中 CUDA 和 PyTorch 兼容的 `vLLM`。在常规 AutoDL PyTorch 镜像中可先尝试：

```bash
python -m pip install vllm
python -c "import vllm; print('vllm: OK')"
```

安装 `vLLM` 后必须重新执行 PyTorch、CUDA 与 `vLLM` 检查，确认三者能够共同工作。

下载 NLTK（自然语言工具包）的句子切分资源：

```bash
python -m nltk.downloader punkt punkt_tab
```

运行本项目自动测试：

```bash
cd /root/paper_reproduction/code
python -m unittest discover -s tests -v
```

全部测试通过后再下载模型和生成数据。

### 1.5 准备 Paul Graham Essays 背景数据

RULER 的单针与多键任务需要 `PaulGrahamEssays.json`。先检查文件：

```bash
test -s /root/paper_reproduction/ref/RULER/scripts/data/synthetic/json/PaulGrahamEssays.json
```

返回值为 `0` 表示文件存在且非空，可跳过本节后续下载命令。返回值不为 `0` 时，在网络稳定的环境执行作者脚本：

```bash

```

该脚本逐页下载文章，AutoDL 网络不稳定时可能出现长时间等待或部分页面失败。此时在网络稳定的本地 WSL 中执行同一脚本：


随后通过 AutoDL 网页文件管理器，将本地生成的 `PaulGrahamEssays.json` 上传到：

```text

```

上传后在 AutoDL 再次执行：

```bash
test -s /root/paper_reproduction/ref/RULER/scripts/data/synthetic/json/PaulGrahamEssays.json

```

### 1.6 开启 AutoDL 学术资源加速代理

模型下载前，在准备执行 `hf download` 的同一个终端中开启 AutoDL 学术资源加速：

```bash
source /etc/network_turbo
env | grep -E '^(http_proxy|https_proxy|HTTP_PROXY|HTTPS_PROXY)='
```

第二条命令应显示当前终端中的代理环境变量。AutoDL 的该服务用于加速 GitHub 和 Hugging Face 等学术资源访问，但官方不承诺其始终稳定；只在下载阶段使用，下载完成后按第 1.9 节关闭。[AutoDL 学术资源加速官方说明](https://api.autodl.com/docs/network_turbo/)

代理环境变量只对当前终端及其子进程生效。不要把 `source /etc/network_turbo` 写入 `.bashrc`，也不要在另一个未开启代理的终端执行后续 `hf download`。

#### 1.6.1 处理 Xet/CAS 的 `401 Unauthorized`

如果 `hf download` 的报错包含 `cas-server.xethub.hf.co`、`CAS Client Error` 和 `401 Unauthorized`，先保留已经下载的文件，不删除模型目录。Hugging Face 默认可能通过 Xet/CAS 下载大文件；代理链路或授权状态异常时，可以关闭 Xet，改用普通 HTTP 下载链路。[Hugging Face 环境变量官方说明](https://huggingface.co/docs/huggingface_hub/package_reference/environment_variables)

在执行下载的同一个终端中运行：

```bash
export HF_HUB_DISABLE_XET=1
export HF_HUB_DOWNLOAD_TIMEOUT=120
```

如果下载 Qwen，直接重新执行第 1.7 节的完整 `hf download` 命令。Qwen 仓库是公开仓库，不需要用 Llama 的许可问题解释该错误。

如果下载 Llama，先检查当前登录账号：

```bash
hf auth whoami
```

输出必须是已经在 Llama 模型页面取得访问权限的账号。如果未登录、账号不一致或许可尚未批准，执行：

```bash
hf auth logout
hf auth login
hf auth whoami
```

确认账号和许可后，重新执行第 1.8 节的完整 `hf download` 命令。不要添加 `--force-download`，也不要删除 `--local-dir` 中已经完成的文件。

若设置 `HF_HUB_DISABLE_XET=1` 后错误堆栈仍然进入 `xet_get`，检查变量是否设置在执行 `hf download` 的同一个终端：

```bash
echo "$HF_HUB_DISABLE_XET"
hf env | grep HF_HUB_DISABLE_XET
```

两处都应显示启用状态。模型下载完成后，在第 1.9 节关闭代理时一并清除这两个临时变量。

### 1.8 申请并下载 Meta-Llama-3.1-8B-Instruct

Llama 3.1 是许可受控模型。先在浏览器打开[Meta-Llama-3.1-8B-Instruct 官方仓库](https://huggingface.co/meta-llama/Llama-3.1-8B-Instruct)，登录 Hugging Face，阅读并接受许可，等待账号获得访问权限。

在 AutoDL 终端登录 Hugging Face：


`hf auth login` 会提示输入访问令牌。令牌只在交互提示中粘贴，不写入命令历史、项目文件或聊天记录。

取得访问权限后下载 Llama：


如果出现 `401` 或 `403`，依次检查：许可申请是否已批准、`hf auth whoami` 是否为获批账号、访问令牌是否具有读取权限。不要通过他人账号或把令牌写进下载命令绕过许可。

检查必要文件：

```bash
test -s /root/autodl-tmp/models/Meta-Llama-3.1-8B-Instruct/config.json
```

### 1.9 关闭 AutoDL 学术资源加速代理

Qwen 与 Llama 下载完成并通过文件检查后，在执行下载的同一个终端中关闭代理：

```bash
unset http_proxy
```

如果 Llama 许可尚未批准，无法立即下载，应先关闭代理；收到许可后重新执行第 1.6 节开启代理，只运行第 1.8 节的 Llama 登录与下载，完成后再次执行本节关闭代理。

### 1.11 启动、检查和切换模型服务

模型服务需要单独占用一个终端。实验命令在另一个终端执行，并重新设置第 1.10 节中的两个环境变量。

#### 1.11.1 启动 Qwen

```bash
export QWEN_MODEL_PATH=/root/autodl-tmp/models/Qwen2.5-7B-Instruct

vllm serve "$QWEN_MODEL_PATH" \
  --served-model-name Qwen2.5-7B-Instruct \
  --port 8000 \
  --max-model-len 8192 \
  --dtype bfloat16
```

#### 1.11.2 启动 Llama

先在 Qwen 服务终端按 `Ctrl+C`，等待进程退出并使用 `nvidia-smi` 确认显存释放，再运行：

```bash
export LLAMA31_MODEL_PATH=/root/autodl-tmp/models/Meta-Llama-3.1-8B-Instruct

vllm serve "$LLAMA31_MODEL_PATH" \
  --served-model-name Meta-Llama-3.1-8B-Instruct \
  --port 8000 \
  --max-model-len 8192 \
  --dtype bfloat16
```

Llama 3.1 8B 的标称上下文长度为 $128\mathrm{k}$，本项目只测试到 $8\mathrm{k}$，因此服务端设置为 $8192$，减少键值缓存占用。若 GPU 不支持 `bfloat16`，先停止实验，由 A 统一确认兼容精度，并保证所有成员记录实际精度。

#### 1.11.3 检查当前服务

在实验终端执行：

```bash
curl -s http://127.0.0.1:8000/v1/models
```

Qwen 服务应返回 `Qwen2.5-7B-Instruct`，Llama 服务应返回 `Meta-Llama-3.1-8B-Instruct`。服务名称必须与 `configs/models/*.yaml` 中的 `model_name` 完全一致。

## 三、阶段二：B、C、D 完成正式实验，A 负责整合

### 3.1 阶段二统一规则

每名成员先完成第一部分的全部准备，并拉取 GitHub `main` 分支。每个模型均按以下顺序执行：

1. 确认已按第 1.9 节关闭下载代理，再启动当前模型服务并检查 `/v1/models`。
2. 用当前模型分词器执行 `prepare`。
3. 执行 `run` 保存原始响应。
4. 执行 `score` 生成逐样本评分。
5. 检查样本、响应、评分和运行日志。
6. 停止当前模型，释放显存后切换另一个模型。

发生中断时重新执行原 `run` 命令，程序会跳过已有成功记录。只补跑失败记录时添加 `--retry-failed`。正式推理开始后不得执行 `prepare --force`，否则可能改变已经使用的样本。

所有成员先执行：

```bash
cd /root/paper_reproduction/code
git pull --ff-only
export QWEN_MODEL_PATH=/root/autodl-tmp/models/Qwen2.5-7B-Instruct
export LLAMA31_MODEL_PATH=/root/autodl-tmp/models/Meta-Llama-3.1-8B-Instruct
```

### 3.2 B：单针双模型主实验

B 负责单针 $2\mathrm{k}$、$4\mathrm{k}$、$8\mathrm{k}$，共 $6$ 个模型—任务单元和 $300$ 次正式调用。

#### 3.2.1 B 运行 Qwen

按第 1.11.1 节启动 Qwen，再执行：

```bash
for cfg in single_2k single_4k single_8k; do
  ruler-repro prepare --config "configs/experiments/${cfg}.yaml" \
    --model-config configs/models/qwen2_5_7b_instruct.yaml
  ruler-repro run --config "configs/experiments/${cfg}.yaml" \
    --model-config configs/models/qwen2_5_7b_instruct.yaml
  ruler-repro score --config "configs/experiments/${cfg}.yaml" \
    --model-config configs/models/qwen2_5_7b_instruct.yaml
done
```

#### 3.2.2 B 运行 Llama

停止 Qwen，按第 1.11.2 节启动 Llama，再执行：

```bash
for cfg in single_2k single_4k single_8k; do
  ruler-repro prepare --config "configs/experiments/${cfg}.yaml" \
    --model-config configs/models/llama3_1_8b_instruct.yaml
```

## 四、阶段三：案例分析、报告与汇报

### 4.1 四人分工

- A：核对联合数据、统稿、解释边界、最终打包与提交。
- B：分析双模型单针结果，撰写单针方法与结果，提供至少两条可回溯案例。

### 4.2 案例分析要求

每条案例至少包含：模型编号、实验编号、样本编号、输入路径、实际输入词元数、目标键、标准答案、原始回答、严格匹配、RULER 宽松匹配、失败类别和判定理由。

只能根据可观察记录描述错误。模型输出命中输入中的其他七位数字时，才标记为干扰项混淆；包含正确数字但带有额外文本时，标记为严格格式失败；接口超时或服务错误归入运行异常。

### 4.3 报告中的实验边界

报告应明确：

- Qwen 与 Llama 分别用自己的分词器和模板生成数据。
- 主指标是严格答案匹配，RULER 宽松匹配作为辅助指标。
- 位置消融在每个模型内部使用同一基础样本的三个配对变体。
- 实测范围只覆盖单针、四针、八针和不超过 $8\mathrm{k}$ 的输入。
- 不宣称复现全部十三项任务，也不根据本项目结果推断 $128\mathrm{k}$ 性能。
