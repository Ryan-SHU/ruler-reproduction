# RULER 双模型复现运行与输出说明指南

## 一、适用方式

将完整 `paper_reproduction` 文件夹上传到 AutoDL，所有命令从 `paper_reproduction/code` 执行。本指南不要求创建隔离虚拟环境，默认使用 AutoDL `base` 环境中已有的 PyTorch。命令中的 A、B、C、D 是组员代号。

两个模型不能共用同一份生成数据。Qwen 和 Llama 分别使用自己的分词器与 RULER 输入模板运行作者生成器，并分别保存样本、响应和评分。

目录中未带模型编号层级的旧阶段一数据和结果仅作历史证据保留。新版命令只读取 `data/.../<model_id>/<experiment_id>/` 和 `results/.../<model_id>/<experiment_id>/`，组员不得把旧目录当作正式输入。

不要把 Hugging Face 令牌、模型权重、密码或个人连接信息放入 `paper_reproduction`。本文件也不规定模型缓存和 `pip` 缓存位置，继续使用服务器已有配置。

## 二、一次性环境检查

进入项目并安装本工程：

```bash
cd ~/paper_reproduction/code
python -m pip install -e .
python -m unittest discover -s tests -v
```

若 `vLLM` 尚不可用，再按照 AutoDL 当前 CUDA 和 PyTorch 环境安装兼容版本。安装后确认：

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
python -c "import vllm; print(vllm.__version__)"
vllm --help
```

RULER 生成器需要 NLTK（自然语言工具包）的句子切分数据：

```bash
python -m nltk.downloader punkt punkt_tab
```

确认作者背景文件存在：

```bash
test -s ../ref/RULER/scripts/data/synthetic/json/PaulGrahamEssays.json
```

如果文件不存在或为空，先在网络稳定的本地 WSL 中运行作者下载脚本，再把生成的 `PaulGrahamEssays.json` 上传到上述路径。AutoDL 网络不稳定时不要反复运行逐网页下载程序。

## 三、模型准备与环境变量

Qwen 模型目录和 Llama 模型目录必须位于项目文件夹之外。Llama 3.1 是许可受控模型，下载前需要在 Hugging Face 模型页接受许可，并在当前终端安全设置访问令牌。不要把令牌写入脚本或文档。

每次打开新终端后设置本机实际路径：

```bash
export QWEN_MODEL_PATH=/root/autodl-tmp/models/Qwen2.5-7B-Instruct
export LLAMA31_MODEL_PATH=/root/autodl-tmp/models/Meta-Llama-3.1-8B-Instruct
```

检查目录：

```bash
test -d "$QWEN_MODEL_PATH"
test -d "$LLAMA31_MODEL_PATH"
```

两个检查均无输出且退出码为 $0$ 才表示目录存在。

## 四、模型服务启动与切换

### 4.1 启动 Qwen

```bash
vllm serve "$QWEN_MODEL_PATH" \
  --served-model-name Qwen2.5-7B-Instruct \
  --port 8000 \
  --max-model-len 8192 \
  --dtype bfloat16
```

保持该终端运行，在另一个终端执行实验命令。若服务器不支持 `bfloat16`，经 A 统一确认后将两个模型都改用环境支持的精度，并在运行记录中注明。

### 4.2 启动 Llama

先用 `Ctrl+C` 停止 Qwen 服务并确认显存释放，再运行：

```bash
vllm serve "$LLAMA31_MODEL_PATH" \
  --served-model-name Meta-Llama-3.1-8B-Instruct \
  --port 8000 \
  --max-model-len 8192 \
  --dtype bfloat16
```

虽然 Llama 3.1 8B 的标称上下文长度为 $128\mathrm{k}$，本项目只测试到 $8\mathrm{k}$，服务端按 $8192$ 配置即可减少长上下文键值缓存占用。

### 4.3 服务检查

在实验终端执行：

```bash
curl -s http://127.0.0.1:8000/v1/models
```

返回的模型名称必须与当前模型配置中的 `model_name` 完全一致。

## 五、阶段一：A 完成双模型小范围闭环

阶段一分别验证 Qwen 与 Llama 的“作者数据生成—服务调用—评分—汇总—案例导出”流程。两种模型各跑单针和四针 $2\mathrm{k}$ 的 $2$ 个试跑样本。

### 5.1 Qwen 闭环

先启动 Qwen 服务，然后执行：

```bash
ruler-repro preflight \
  --config configs/pilot/pilot_single_2k.yaml \
  --model-config configs/models/qwen2_5_7b_instruct.yaml \
  --check-server

ruler-repro all \
  --config-dir configs/pilot \
  --include-pilot \
  --model-config configs/models/qwen2_5_7b_instruct.yaml
```

### 5.2 Llama 闭环

停止 Qwen、启动 Llama，再执行：

```bash
ruler-repro preflight \
  --config configs/pilot/pilot_single_2k.yaml \
  --model-config configs/models/llama3_1_8b_instruct.yaml \
  --check-server

ruler-repro all \
  --config-dir configs/pilot \
  --include-pilot \
  --model-config configs/models/llama3_1_8b_instruct.yaml
```

### 5.3 阶段一验收

以下目录必须同时存在：

```text
data/manifests/qwen2_5_7b_instruct/pilot_single_2k/
data/manifests/llama3_1_8b_instruct/pilot_single_2k/
results/raw/qwen2_5_7b_instruct/pilot_single_2k/
results/raw/llama3_1_8b_instruct/pilot_single_2k/
results/scored/qwen2_5_7b_instruct/pilot_single_2k/
results/scored/llama3_1_8b_instruct/pilot_single_2k/
```

A 人工核对两种模型各至少一条样本：标准答案确实位于输入中，原始响应可读，严格匹配与宽松匹配判定正确，两个模型的样本编号和目录彼此独立。

### 5.4 生成阶段一双模型联合汇总

Qwen 与 Llama 的 `all` 命令会依次更新公共汇总文件。两个模型都完成后，A 需要再执行一次双模型联合汇总，确保交给组员的表格和图形同时包含两种模型：

```bash
ruler-repro summarize \
  --config-dir configs/pilot \
  --include-pilot \
  --model-config configs/models/qwen2_5_7b_instruct.yaml \
  --model-config configs/models/llama3_1_8b_instruct.yaml

ruler-repro cases \
  --config-dir configs/pilot \
  --include-pilot \
  --model-config configs/models/qwen2_5_7b_instruct.yaml \
  --model-config configs/models/llama3_1_8b_instruct.yaml \
  --minimum-cases 4
```

### 5.5 A 向 B、C、D 移交的内容

第一部分是阶段二运行必需内容，通过 GitHub 仓库的 `main` 分支发送：

- `configs/`：两个模型、七个主实验、三个位置消融和试跑配置。
- `src/`、`scripts/` 与 `tests/`：完整程序、迁移工具和自动测试。
- `docs/`、`README.md`、`pyproject.toml` 与 `data/README.md`：设计、逐步导读、运行命令、依赖和数据说明。
- A 已验证的提交编号。B、C、D 应从该提交拉取代码，避免分别传送不同版本的压缩包。

第二部分是证明阶段一已经跑通的证据，需要通过组内网盘或聊天文件单独发送，因为这些运行产物已被 `.gitignore` 排除：

- `data/generated/qwen2_5_7b_instruct/pilot_single_2k/` 与 `pilot_multikey4_2k/`。
- `data/generated/llama3_1_8b_instruct/pilot_single_2k/` 与 `pilot_multikey4_2k/`。
- 两个模型在 `data/manifests/<model_id>/` 下对应的四个试跑样本目录。
- 两个模型在 `results/raw/<model_id>/` 下对应的响应、`run_config.yaml` 和 `run.log`。
- 两个模型在 `results/scored/<model_id>/` 下对应的逐样本评分。
- 联合生成的 `results/summary/`、`results/figures/` 和 `results/cases/`。

第三部分是简短的运行环境与问题记录，至少说明 GPU 型号、Python、PyTorch、CUDA、`vLLM` 和 `transformers` 版本，两个模型权重所对应的准确版本或提交标识，阶段一实际调用数、失败数、重试数，以及仍未解决的问题。该记录不得包含访问令牌、密码、服务器登录信息或模型权重。

阶段一的试跑数据只用于说明流程已经跑通。B、C、D 在阶段二仍需按照各自命令，分别用 Qwen 和 Llama 的分词器重新生成正式实验数据；不得把阶段一的每组 $2$ 条样本扩充或复制为正式结果。

## 六、阶段二统一规则

每位成员拿到同一份完整 `paper_reproduction`。正式运行前执行第二节和第三节检查。每个模型都遵循以下顺序：

1. 启动当前模型服务。
2. 对自己负责的配置执行 `prepare`，用当前模型分词器生成数据。
3. 执行 `run` 保存原始响应。
4. 执行 `score` 生成逐样本评分。
5. 检查样本数、响应数和失败记录。

发生中断时重新执行原 `run` 命令，已有成功记录会被跳过。只重试失败记录时加入 `--retry-failed`。不得使用 `prepare --force` 重建已经开始正式推理的数据。

## 七、B：单针双模型主实验

B 负责单针 $2\mathrm{k}$、$4\mathrm{k}$、$8\mathrm{k}$，两个模型合计 $6$ 个实验单元、$300$ 次正式调用。

### 7.1 Qwen

启动 Qwen 后执行：

```bash
for cfg in single_2k single_4k single_8k; do
  ruler-repro prepare --config "configs/experiments/${cfg}.yaml" \
    --model-config configs/models/qwen2_5_7b_instruct.yaml
  ruler-repro run --config "configs/experiments/${cfg}.yaml" \
    --model-config configs/models/qwen2_5_7b_instruct.yaml
  ruler-repro score --config "configs/experiments/${cfg}.yaml" \
    --model-config configs/models/qwen2_5_7b_instruct.yaml
done
```

### 7.2 Llama

停止 Qwen、启动 Llama 后执行：

```bash
for cfg in single_2k single_4k single_8k; do
  ruler-repro prepare --config "configs/experiments/${cfg}.yaml" \
    --model-config configs/models/llama3_1_8b_instruct.yaml
  ruler-repro run --config "configs/experiments/${cfg}.yaml" \
    --model-config configs/models/llama3_1_8b_instruct.yaml
```

## 九、D：八针主实验与双模型位置消融

D 负责两个模型的八针 $8\mathrm{k}$ 主实验，共 $100$ 次调用；另负责两个模型的三个证据位置条件，共 $300$ 次调用。

### 9.1 当前模型的八针主实验

启动当前模型服务，将下面的 `<MODEL_CONFIG>` 替换为当前模型配置：

```bash
ruler-repro prepare --config configs/experiments/multikey8_8k.yaml \
  --model-config <MODEL_CONFIG>
ruler-repro run --config configs/experiments/multikey8_8k.yaml \
  --model-config <MODEL_CONFIG>
ruler-repro score --config configs/experiments/multikey8_8k.yaml \
  --model-config <MODEL_CONFIG>
```

Qwen 的 `<MODEL_CONFIG>` 为 `configs/models/qwen2_5_7b_instruct.yaml`，Llama 的值为 `configs/models/llama3_1_8b_instruct.yaml`。两种模型分别执行一次。

### 9.2 当前模型的位置消融

消融依赖同一模型的基础 `single_8k` 样本。D 即使不运行该主实验，也要先为当前模型执行一次 `prepare single_8k`：

```bash
ruler-repro prepare --config configs/experiments/single_8k.yaml \
  --model-config <MODEL_CONFIG>
ruler-repro prepare-ablation --config-dir configs/ablations \
  --model-config <MODEL_CONFIG>
ruler-repro run --config-dir configs/ablations \
  --model-config <MODEL_CONFIG>
ruler-repro score --config-dir configs/ablations \
  --model-config <MODEL_CONFIG>
```

先为 Qwen 执行上述流程，再切换服务并为 Llama 执行。不要把 B 回传的 Qwen 基础数据当作 Llama 基础数据。

## 十、每人完成后的检查

以下命令以某一实验为例，其他实验替换目录名：

```bash
wc -l data/manifests/qwen2_5_7b_instruct/single_2k/samples.jsonl
wc -l results/raw/qwen2_5_7b_instruct/single_2k/responses.jsonl
wc -l results/scored/qwen2_5_7b_instruct/single_2k/scores.jsonl
```

正式单元的三个结果应各为 $50$ 行。响应文件可能因失败重试包含同一样本的多条记录，程序汇总时使用该样本的最新记录；若行数不等于 $50$，应查看 `run.log`，再用 `--retry-failed` 补跑。

每位成员向 A 发送：

- 自己负责的 `data/generated/<model_id>/<experiment_id>/`。
- 自己负责的 `data/manifests/<model_id>/<experiment_id>/`。
- 对应的 `results/raw/<model_id>/<experiment_id>/` 与 `results/scored/<model_id>/<experiment_id>/`。
- 模型名称、模型目录所对应的版本或提交标识、GPU 型号、PyTorch 与 `vLLM` 版本。
- 实际调用数、失败数、重试数和未解决错误。
- 每个模型至少两条候选失败或边界案例编号及简要说明。

D 还需发送六个位置消融目录，并确认每个模型在三个位置上都具有 $50$ 条记录。

## 十二、输出文件说明

- `responses.jsonl`：原始模型回答、状态、耗时、接口词元数和尝试次数。
- `run_config.yaml`：当前模型与实验条件的冻结快照。
- `run.log`：开始、结束、逐样本状态和重试记录。
- `scores.jsonl`：严格匹配、RULER 宽松匹配和失败类别。
- `model_experiment_metrics.csv`：按模型和实验条件汇总的正确数、正确率、$95\%$ 置信区间、调用量和实际长度。
- `plot_data.csv`：绘图所需的精简汇总。
- `position_ablation_metrics.csv`：双模型三个位置条件的汇总结果。
- `position_ablation_paired_cases.csv`：三个证据位置的逐样本配对结果。
- `position_ablation_statistics.csv`：Cochran 的 $Q$ 检验、McNemar 检验和 Holm 阈值。
- `results/figures/`：双模型长度曲线、针数对照和位置消融曲线。
- `results/cases/`：联合案例及按模型编号划分的失败或边界案例。

## 十三、阶段三简要安排

B 分析单针双模型结果，C 分析四针双模型结果，D 分析八针与位置消融，A 负责联合核验和统稿。四人共同完成报告与幻灯片，并确保每项数字能回溯到样本清单、原始响应和评分记录。

报告必须同时说明：两个模型各自生成数据；严格匹配与宽松匹配的区别；位置消融的配对方法；实际测试只覆盖单针、多键和不超过 $8\mathrm{k}$ 的范围。不得宣称复现全部十三项任务或验证 $128\mathrm{k}$ 性能。
